## Backend

`rfis` table:
- `id`, `tenant_id`, `project_id` FK projects NOT NULL
- `rfi_number` text — generated by M33 numbering scheme (key: `RFI`); if no
  numbering scheme defined for the tenant, fall back to sequential integer
  formatted as `RFI-<n>`
- `raised_by` uuid FK app_users
- `addressed_to_user_id` uuid nullable FK app_users
- `addressed_to_contact_id` uuid nullable FK crm_contacts (M10 CRM contacts)
- `subject` text NOT NULL
- `description` text
- `date_raised` date NOT NULL default today
- `date_required` date nullable (response needed by)
- `date_responded` date nullable
- `response` text nullable
- `status` text default 'open' check ('open','responded','closed','cancelled')
- `reference_document_ids` uuid[] default '{}'
- `created_at` timestamptz default now()

Permission: `engineering.rfi.manage` — granted to `role.platform_administrator`,
`role.lead_engineer`, `role.project_engineer`, `role.project_manager`.

Endpoints:
- `GET /projects/:projectId/rfis` — list, with status filter
- `POST /projects/:projectId/rfis` — create (guarded)
- `GET /rfis/:id`
- `PATCH /rfis/:id` — update, including respond (sets response + date_responded,
  transitions status to 'responded') and close/cancel (guarded)

## Frontend

Tab "RFIs" within `ProjectDetailPage`.
- List: rfi_number, subject, status badge, date_raised, date_required (with
  overdue indicator if past and still open), addressed_to
- PermissionGate on New RFI button
- Create form: subject, description, date_required, addressed_to picker
  (UserPicker or manual text if external)
- Detail panel (slide-over): full fields, Respond form (response text,
  date_responded), Close / Cancel buttons — all guarded
- Reference doc IDs → link to document detail
